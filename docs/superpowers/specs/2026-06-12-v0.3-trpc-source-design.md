# v0.3 tRPC source design

## Context

Bridgent v0.1 and v0.2 validated the explicit server-file runtime model:
users compose source adapters in TypeScript and expose the resulting tools over
stdio, Streamable HTTP, or a Web Standard handler.

The shipped source coverage is now:

- hand-written Zod tools
- OpenAPI 3.x
- Prisma 6.x read tools with optional audited writes
- Drizzle read-only `findMany`

The next product gap is application-code exposure. Many TypeScript apps already
describe business operations as tRPC routers with input parsers and typed
procedure paths. Requiring those teams to rewrite each procedure as a Bridgent
Zod tool creates avoidable duplication.

## Goal

v0.3 should add a focused `@bridgent/source-trpc` package and the minimum shared
metadata needed to make generated tools understandable.

The v0.3 product theme is:

> expose existing typed application procedures as MCP tools without hiding the
> explicit server-file model.

## Package

Add `packages/source-trpc` published as `@bridgent/source-trpc`.

Expected public entry point:

```ts
import { fromTrpc } from '@bridgent/source-trpc'

const tools = fromTrpc({
  router: appRouter,
  createContext: async () => ({ userId: 'demo' }),
  toolPrefix: 'app',
  procedureFilter: path => path.startsWith('public.'),
  allow: {
    mutating: false,
  },
})
```

## Supported tRPC surface

### Procedures

- `query`: exposed by default as read tools.
- `mutation`: disabled by default; exposed only through explicit mutating
  controls and a procedure allowlist.
- `subscription`: not supported in v0.3 because MCP tool calls are
  request/response and Bridgent does not own streaming orchestration.

### Router shape

- Support tRPC v10/v11 router objects that can create a caller in-process.
- Execute through the router caller API rather than HTTP round-trips.
- Nested router paths become stable tool names.

### Input parsers

- Zod-backed procedure inputs should map to MCP input schemas.
- Procedures without input should expose an empty object schema.
- Unsupported parser shapes must fail clearly during tool generation unless the
  user explicitly filters those procedures out.
- Do not generate permissive `any` schemas as a fallback.

### Context

- `createContext` can be sync or async.
- Context creation remains application-owned. Bridgent should not invent auth,
  sessions, or request identity.
- The invocation context should include enough information for future host
  metadata, but v0.3 does not need a full HTTP request abstraction.

## Tool naming

Rules:

- Default prefix: `trpc`.
- Procedure path `user.getById` becomes `trpc_user_getById`.
- Optional `toolPrefix` replaces the default prefix.
- Generated names must be stable across runs.
- Collisions throw during tool generation.
- Names should use the same slugging conventions as existing source packages
  where possible.

## Mutation safety

Mutations are materially different from queries and must not be exposed by a
simple broad toggle.

Initial v0.3 mutation controls:

- default: no mutations
- `allow.mutating: true` required
- non-empty mutation allowlist required
- mutation names in the allowlist must use final generated tool names or exact
  procedure paths; the implementation should pick one and document it

If mutation audit/preview support is added later, it should reuse the Prisma
write lessons: explicit allowlist, preview where feasible, and fail-closed
audit. It is not required for the v0.3 tRPC MVP.

## Source capability metadata

Add a small additive metadata contract that source adapters may attach to
generated tools.

Minimum fields:

- source kind: `zod`, `openapi`, `prisma`, `drizzle`, `trpc`
- source name or namespace
- original operation/model/table/procedure path
- capability: `read` or `write`
- safety flags:
  - requires auth/context
  - has audit
  - has preview token
  - row/output limit if applicable

Metadata consumers:

- docs examples
- `bridgent inspect` console hints
- future custom inspector UI
- future policy DSL

This must be additive and must not break the current `BridgentTool[]` contract.

Required before claiming v0.3 complete:

- focused `@bridgent/source-trpc` tests
- example smoke coverage where practical
- docs lint/build
- full gate: `pnpm turbo run build test typecheck lint`

## Explicit non-goals

- No GraphQL source adapter in v0.3.
- No tRPC subscriptions.
- No hosted control plane.
- No Bridgent Hub or package registry.
- No OAuth2 platform flow.
- No custom inspector web app.
- No implicit mutation exposure.
- No permissive input schemas for unsupported parser types.
